Was nach dem Merge **von uns** angepasst werden muss (nichts davon macht Git von allein):

1. **Pfad der Extensions.** `EXT_DIR` steht doppelt fest im Code: `eltern/extensions.ts` (`/home/dietpi/.mupibox/extensions`, API) und
   `backend-player/src/extensions.js` (Player). Beide über `paths.ts` bzw. `mupi_paths.sh` führen. Vorschlag: `data/extensions/`
   (`data/` fasst ein Update nie an; die Einstellungen und Daten einer Extension gehören dorthin), mit einem Umzugsschritt in
   `migrate_layout.sh` (`~/.mupibox/extensions` → `data/extensions`, nur wenn vorhanden). Bleibt der Ordner, wo er ist, überlebt er Updates
   auch (er liegt außerhalb von `server/`), gehört aber nicht zu den vier Ordnern.
2. **Winamp-Skins.** `winamp-skin.ts` schreibt nach `~/.mupibox/Sonos-Kids-Controller-master/www/theme-data/winamp/…`. Das läuft über den
   Link weiter und `theme-data` übernimmt das Update (`cp -an`), sollte aber über `WWW_DIR` aus `paths.ts` gehen.
3. **Neustart der Dienste.** `restartServices()` der Extensions startet `server` und `spotify-control` mit `pm2`: die Namen sind in `layout`
   unverändert, hier ist nichts zu tun.
4. **Tests** (`extensions.spec.ts` u. a.) und `docs/extensions.md` (Pfade) nachziehen.

Vorgehen, wenn es soweit ist: einen Zweig von `wowa/layout` anlegen, `dev5.1` hineinmergen, die vier Dateien verschieben, die Importe
anpassen, `npm test`, dann `deploy.zip` neu bauen. Waldemar hat angeboten, beim Umziehen nach `app-api/` zu helfen.

## 2. Die Schnittstelle für Foto, Immich, Taster, NFC

Was heute geht (`hostApi` 2, siehe `docs/extensions.md`), und was eine Foto/Immich-Extension zusätzlich bräuchte:

| Bedarf | Stand |
|---|---|
| Eigene Seite im Display (Vollbild) | ✔ `api.overlay.open` |
| Reiter in der Kategorie-Leiste, Symbol in der Kopfzeile | ✔ `api.tabs`, `api.header` |
| Einstellungen mit Prüfung, Geheimnisse (API-Schlüssel) | ✔ `settings` (`secret`, `options`, `min`/`max`, `pattern`) |
| Auswahl/Suche in der Webapp (Alben, Orte) | ✔ `ui` mit `choices` und `lookup` – **aber** ein `lookup` sucht erst ab zwei Buchstaben; für „alle Immich-Alben anzeigen“ fehlt ein Durchblättern ohne Suchwort |
| Eigener Code auf der Box (Abruf, Zwischenspeicher, Bilder ausliefern) | ✔ API-Teil: `host.route`, `host.settings()`, `host.dataDir`, eigene Zeitgeber |
| Dateien einer Extension ausliefern | ✔ `/ext/<id>/…` (nur `display.js` und was es lädt); große Bilder besser über eine eigene Route des API-Teils |
| **Ruhezustand / Bildschirmschoner** („Fotos zeigen, wenn die Box nichts tut“) | ✘ fehlt: das Display kennt „untätig seit N Sekunden“ und „wieder berührt“ nur im Kern. Vorschlag: `api.idle.on(seconds, { start(), stop() })` |
| **Eigene Nutzungsdauer** der Fotoanzeige | ✘ fehlt: die Spielzeit des Kerns (Tagesbudget in `data/`) ist für Wiedergabe gedacht. Es braucht eine Entscheidung: zählt die Fotoanzeige in dieselbe Zeit oder in eine eigene, und wo steht sie (Manifest oder Kern)? |
| Quellen wie NAS oder lokal für Fotos | Sache der Extension (Dateien lesen); `host.albums.register` ist nur für **Audio** im Player |
| Zugriff auf Gruppen/Hardware | ✘ `system.groups` erlaubt nur `cdrom`, `audio`, `video`, `plugdev` |

Für **Taster und NFC** (Andreas): zusätzlich `gpio`, `spi`, `i2c` bei `groups` (jeweils mit Prüfung), im Player `host.playback.pause()`, `next()`,
`previous()` (heute gibt es nur `stop()`) und ein Ereignis, wenn ein Tag gelesen wird, das ein Album startet (`host.albums`/`player.open`).

Reihenfolge, damit Waldemar aufsetzen kann: zuerst das Zusammenführen mit `layout` (Abschnitt 1), dann `api.idle` und die Entscheidung zur
Nutzungsdauer. Das Wetter (`extensions/weather/`) ist ein gutes Muster für eine Extension mit Webapp-Einstellungen, API-Teil und Vollbild-Seite.

## 3. `layout` auf dem Pi 5 testen

**Vorher:**
- Eine Sicherung in der Webapp (Einstellungen › Sicherungskopie) herunterladen.
- Wichtig: `layout` enthält **nichts von `dev5.1`** – keine Extensions, kein Wetter, keine Uhr, kein Winamp-Theme. Auf einer Box mit unseren
  Extensions geht es danach nicht mit `branch` zurück (ein älterer Zweig lässt sich auf 5.1 nicht mehr per `branch` installieren), nur über einen
  **Kanal** (stable, beta oder dev). Am besten also nicht auf der Box, auf der `dev5.1` entwickelt wird.
- Notieren: Version vorher (Webapp › Über die Box), freier Speicher (`df -h /`), die Start-Zeit (11 s).

**Installation** (Waldemars Befehl, auf der Box ausführen):

```bash
curl -fsSL https://raw.githubusercontent.com/wowa1990/MuPiBox/layout/update/start_mupibox_update.sh | sudo bash -s -- branch layout wowa1990/MuPiBox
```

**Danach prüfen:**
1. Die Box startet neu und kommt hoch (Start-Zeit?). Display zeigt die Bibliothek.
2. Ordner: `ls -la ~/.mupibox` zeigt `server/`, `player/`, `data/`, `cache/`; `Sonos-Kids-Controller-master` und `spotifycontroller-main`
   sind Links (`ls -l`).
3. Bibliothek, Einstellungen, Alben und Cover sind noch da (Webapp und Display); eine Wiedergabe starten und stoppen; die Fortsetz-Position bleibt.
4. Webapp: Anmelden, Einstellungen öffnen, ein paar Werte ändern und speichern. `http://<box>/admin.php` führt zur App.
5. Spotify-Anmeldung und Lautstärke; falls vorhanden NAS-Quelle und Bluetooth.
6. `pm2 list`: `server` und `spotify-control` laufen. Log in `~/.mupibox/data/logs/`.
7. Ein zweites Update (gleicher Befehl) läuft ohne Fehler durch, und danach ist alles noch da.
8. Zurück: Webapp › Update › Kanal **dev** oder **stable** wählen (nicht `branch`).

**Berichten an Waldemar:** Version vorher/nachher, Start-Zeit, was bei 1–8 nicht stimmte, die letzten Zeilen des Update-Logs
(`~/.mupibox/data/logs/` bzw. die Ausgabe des Befehls).
